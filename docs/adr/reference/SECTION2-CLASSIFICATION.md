# نموذج تصنيف قيم القسم 2 من ADR-08 (المرجع النقي)

> هذا نموذج مرجعي **نقي** لقرار بوابة الخروج — ليس بوابة `@ir/egress` ولا يدّعي أنه كذلك.
> نجاح اختباراته يثبت صحة قواعد هذا المرجع فقط، ولا يثبت تنفيذ بوابة تشغيلية ولا منع نقل فعلي.
> `@ir/egress` غير موجود بعد (رهن اعتماد ADR-08)، لذا «النتيجة الفعلية» لكل حالة تبقى: **غير مثبتة تنفيذياً**.

## المصدر الحاكم

- تعريف القسم 2 وسلوكه: `docs/adr/ADR-08-egress-gateway.md` (القسم 2: كل طلب مربوط بقضية وغرض).
- تعريف أنواع الحساسية `Sensitivity`: `packages/schema/src/primitives.ts` — مغلقة على `normal | natural_person_gate | minor`.
- تعريف حساسية القضية `CaseSensitivity`: `packages/schema/src/case.ts` — مغلقة على `standard | sensitive | restricted`.
- تعريف `sends` في ADR-08: **أنواع بيانات القضية** التي يحملها الطلب (في الرابط أو الترويسات أو الجسم)، معلنة في بيان المحوّل — ليست أسطح الطلب.
- تصنيف P1-008: 319 نوعاً `normal` و52 نوعاً `natural_person_gate` في `packages/core/identifiers/`.

## القاعدة

القرار دالة نقية: `(input) => { decision, reason }` حيث `decision` هو `"allow" | "deny"` و`reason` سلسلة سبب موثقة.

### ترتيب الفحص (كل فحص يُرجع أول رفض)

1. **`missing_case`** — `caseId` أو `purposeRef` غائبان => رفض قبل أي DNS.
2. **`unclassified_data`** — قيمة `sensitivity` **غير موجودة في المجموعة المغلقة** أو غير مقدمة (غياب التصنيف) => رفض. **الغياب لا يصبح سماحاً تلقائياً أبداً.**
3. **`natural_person`** — أي بيانات `natural_person_gate` أو قضية `sensitive`/`restricted` بلا سياسة P2-013 معتمدة => رفض (الافتراضي رفض كله).
4. **`undeclared_data`** — نوع بيانات موجود في الطلب (الرابط/الترويسات/الجسم) **غير معلن** في `sends` => رفض.
5. **`minor`** — بيانات `minor` => توقف التوسيع التلقائي (E-08) وليس رفضاً بالضرورة؛ يُعامل كقرار مشروط.
6. **`allow`** — كل ما سبق اجتاز.

### قاعدة الرفض الافتراضي للتصنيف المفقود

**أي قيمة غير قابلة للتصنيف بثقة تُرفض** بسبب مستقل موثق (`unclassified_data` أو `unclassifiable`):
- `sensitivity` غير موجودة في المجموعة المغلقة => `unclassified_data`.
- `sensitivity` غائبة كلياً (undefined/null) => `unclassified_data`.
- نوع بيانات في الطلب لا يمكن جرد نوعه (جسم اعتباطي لا يمكن تحليله) => `unclassifiable` — **لا يُسمح بالمرور**.

### التمييز بين غياب `sends` وقائمة فارغة

- `sends` **غير موجودة** في البيان => **خطأ في البيان** => رفض قبل أي DNS (`missing_manifest`).
- `sends` **قائمة فارغة** `[]` => البيان صالح؛ لا يُسمح بإرسال أي نوع بيانات قضية؛ أي بيانات موجودة => `undeclared_data`.

### خفض الحساسية (تحويل التصنيف)

- التصنيف يُستمد من **السجل الموثوق** (`packages/core/identifiers/`) لا من ادعاء المحوّل.
- إذا حاول المحوّل تمرير بيانات `natural_person_gate` تحت وسم أخف (`normal`)، المرجع يرفض لأن **نوع البيانات** يُجرد من السجل، لا من وسم الطلب.

## ما لا يدّعيه هذا المرجع

- لا يدّعي اكتشاف كل بيانات جسم اعتباطي — جرد البيانات مسؤولية البوّابة التنفيذية؛ عند تعذّر الجرد، القرار `unclassifiable` (رفض).
- لا يثبت منع النقل الفعلي — هذا دور البوابة التشغيلية مع شاهد النقل الوهمي (T-SEC-SSRF-COVERAGE).
- لا يعتمد إلا بعد اعتماد ADR-08؛ يظل مقترحاً مرتبطاً بقرار المالك.

## ربط الاختبار

الاختبار في `docs/adr/reference/section2-classification.test.ts` يغطي: القيم الفعلية، التصنيف المفقود والمجهول، غياب البيان، النوع غير المعلن في كل سطح، خفض الحساسية، الحمولات غير القابلة للتصنيف، والقبول الصحيح. توقعات الاختبار مستقلة عن جدول القرار نفسه (قيم متوقعة مكتوبة يدوياً لكل حالة).
