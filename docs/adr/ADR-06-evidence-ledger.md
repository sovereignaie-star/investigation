# ADR-06: سجل أدلة بسلسلة SHA-256 + JCS + Ed25519

| البند | القيمة |
|---|---|
| الحالة | مُقرّر بتفويض ومُنفّذ: السلسلة P1-009، الأدلة الخام P1-010، التوقيع ونقاط التثبيت P1-011 |
| التاريخ | 2026-10-10 |
| المرجع | `docs/ROADMAP.md` 4.3 (D1)، 5.5؛ `packages/ledger` |

## السياق

قيمة المنصة أن كل نتيجة تُثبت بمصدرها ولا تُعدّل بصمت (D1). يجب أن يُكتشف تعديل أي بايت، وحذف أي إدخال أو إعادة ترتيبه، وأن تكون التجزئة حتمية عبر الأجهزة واللغات.

## القرار

| الجانب | القرار |
|---|---|
| التسلسل | JCS وفق RFC 8785. يُرفض ما ليس JSON صرفاً (`undefined`، `NaN`، `bigint`، `Date`، الكائنات غير المجردة، المراجع الدائرية، أنصاف أزواج UTF-16) بدل إسقاطه أو تحويله بصمت |
| التجزئة | `entryHash = SHA-256(UTF-8(JCS(["ir-ledger/1", prevHash, seq, kind, at, actor, payload])))`. تغطي كل الحقول المحفوظة، ومنها `at` و`actor` اللذان لم تذكرهما صيغة 5.5 الأولى. وسم الصيغة `ir-ledger/1` يفصل المجال ويُرفع بقرار جديد إن تغيّرت الحقول |
| البداية | الإدخال `seq = 0` وحده بـ `prevHash = null` |
| الإضافة فقط | الواجهة `append` و`entries` و`head` فقط؛ الإدخالات مجمّدة، والحمولة تُلتقط عند الإضافة؛ المخزن الفاسد يُرفض عند الفتح |
| التحقق | `verify()` يعيد كل الأخطاء بموضعها: `entry_hash` (تعديل)، `seq` و`prev_hash` (حذف أو إدراج أو ترتيب)، `head` و`length` (قص الذيل مقابل رأس أو طول معروف) |
| القص | البادئة سلسلة صحيحة بذاتها، فلا يُكتشف قص الذيل إلا برأس منشور أو موقّع: نقاط تثبيت Ed25519 (P1-011) وختم RFC 3161 اختياري |
| الأدلة الخام | `blobs/<sha256[0:2]>/<sha256>` مضغوطاً بـ zstd؛ العنوان تجزئة البايتات قبل الضغط، وتُعاد في كل قراءة؛ الطلب يُنقّح من الاعتمادات قبل الحفظ؛ إدخال `evidence.stored` يحمل سجل `Evidence` |
| نقطة التثبيت | `ir-checkpoint/1` = `{format, length, head, root, at, keyId}`؛ `root` جذر Merkle وفق RFC 9162 (ورقة `SHA-256(0x00‖h)`، عقدة `SHA-256(0x01‖l‖r)`) فوق `entryHash` للإدخالات `[0, length)` |
| التوقيع | Ed25519 على UTF-8(JCS(payload))، بترميز base64url. `keyId = "ed25519:" + أول 16 حرفاً سداسياً من SHA-256(المفتاح العام الخام)`. المفتاح الخاص في `installation.key` (PKCS#8، 0600) ولا يدخل السلسلة |
| الكشف | `verifyCheckpoint` يعيد `key` و`signature` و`truncated` و`head` و`root`؛ إعادة كتابة التاريخ مع إعادة حساب التجزئات تمر في `verify` وتسقط هنا (T-LED-013) |

## البدائل

ترميز ثنائي مخصص (أسرع لكنه غير قابل للتحقق بأدوات عامة)؛ JSON.stringify بلا تطبيع (غير حتمي في ترتيب المفاتيح والأرقام)؛ شجرة Merkle لكل إدخال (تُستعمل لنقاط التثبيت وإثباتات التضمين فقط)؛ توقيع كل إدخال (مكلف ولا يكشف القص وحده)؛ ECDSA P-256 (توقيع غير حتمي، ومفاتيح أكبر).

## العواقب

السلسلة قابلة للتحقق بأي لغة فيها SHA-256 وJCS. كل تغيير في الحقول المجزّأة يتطلب صيغة جديدة `ir-ledger/2` وترحيلاً.
