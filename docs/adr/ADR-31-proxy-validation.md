# ADR-31: التحقق عبر الوكيل — جدول مسارات مع وضع مشدد افتراضي واستثناء Tor صريح

## السياق

النقل الحالي (`packages/egress/src/node-transport.ts`) ينص حرفياً «لا HTTP_PROXY/HTTPS_PROXY ولا نمرر وكيل» ويتصل بـIP مثبّت بتحقق TLS من اسم المضيف، مع فحوص SSRF وسياسة العناوين تُقيَّم على IP محلول محلياً. دعم الوكيل إعادة صياغة معمارية لهذا النموذج (ADR-08) وليس توسعة صامتة: عبر وكيل، حل DNS قد يحدث عند الوكيل/المخرج، فأي عنوان «تحققنا» منه قد لا يكون العنوان الذي يتصل به المخرج فعلاً.

قرار المالك (2026-10-18): الخيار (3) من خطة #212 مع تقييد حاكم — **الفرق ليس «حسب نوع الوكيل» بل حسب الحاجة الفعلية**: وضع مشدد افتراضي لكل وكلاء HTTP CONNECT وSOCKS5 غير Tor (تثبيت IP)، واستثناء صريح واحد لـTor (النطاق).

## القرار (صياغة المالك الحاكمة)

### جدول المسارات

| المسار | ما يُرسل إلى الوكيل | DNS | فحوص SSRF/العناوين | السجل |
|---|---|---|---|---|
| `direct` (القائم) | — | محلي (ADR-08) | كاملة على IP المحلول محلياً | حدث الشبكة القائم |
| `proxy-http-connect` | **IP** (لا نطاق)؛ SNI = النطاق للتحقق من الشهادة | **محلي — الوكيل ينقل بايتات فقط ولا يحل DNS** | كاملة على IP المحلول محلياً قبل الإرسال | حدث الشبكة + حقل `route` إلزامي |
| `proxy-socks5` (غير Tor) | **IP** (لا نطاق) | محلي — كـ`proxy-http-connect` | كاملة على IP المحلول محلياً | حدث الشبكة + حقل `route` إلزامي |
| `tor` | **النطاق** (لا IP — جوهر Tor) | عند المخرج (خارج تحكمنا) | **قائمة حجب الدومينات الحساسة** (أدناه) + حد معدل منفصل أدنى | حدث تدقيق لكل طلب Tor: المضيف، الطابع الزمني، القضية |

### الوضع المشدد (افتراضي) — كل وكيل HTTP CONNECT أو SOCKS5 غير Tor

1. **IP مثبت محلياً**: DNS محلي + فحوص SSRF على العنوان قبل أي إرسال.
2. **إرسال IP إلى الوكيل (لا نطاق)**، مع SNI = النطاق للتحقق من الشهادة.
3. **الوكيل ينقل بايتات فقط، لا يحل DNS** — يبقى ضمان SSRF كاملاً، لا DNS-rebinding عبر المخرج.

### وضع Tor (استثناء صريح)

1. **النطاق يُرسل (لا IP)** — هذا جوهر Tor.
2. **لا يُفعَّل Tor تلقائياً أبداً** — يتطلب علم صريح (`--via-tor` أو حدث تفعيل في القضية).
3. **قائمة حجب دومينات حساسة**: `localhost`، `*.local`، `*.internal`، `127.*`، `10.*`، `192.168.*`، `172.16.*..172.31.*`، `169.254.*`، ونطاقات الإرسال الداخلية المعتمدة في سياسة العناوين — الطلب إليها عبر Tor مرفوض فاشلاً-مغلق.
4. **حد معدل منفصل أدنى** لمسار Tor.
5. **سجل تدقيق لكل طلب Tor**: المضيف، الطابع الزمني، القضية.
6. **المخاطرة المتبقية موثقة صريحة في DECLARED_LIMITS (L-35) — لا إخفاء**: DNS-rebinding عبر مخرج Tor نحو شبكة داخلية (خارج قائمة الحجب) لا يمكن استبعاده من جانبنا؛ التخفيف هو قائمة الحجب + حد المعدل + السجل الكامل.

### قواعد عامة (كل المسارات)

- **حقل `route` إلزامي في أحداث الشبكة** — كل طلب يسجّل مساره (direct/proxy-http-connect/proxy-socks5/tor) في الأحداث والإسقاطات.
- **اعتماد الوكيل في الخزنة**: المضيف + المنفذ + الاعتمادات إن لزم — لا ملف إعدادات.
- **فشل-مغلق: فشل الوكيل = فشل الطلب، لا سقوط إلى direct** — أي مسار وكيل معطَّل يرفض الطلب ولا يعيد المحاولة مباشرة.

### البنود المرافقة المعتمدة (من #212)

- **ب (البروتوكولات):** HTTP CONNECT + SOCKS5 فقط — لا واجهة Tor منفصلة (Tor عبر SOCKS5 إلى SocksPort 9050).
- **ج (الاعتماديات):** تنفيذ داخلي بلا حزم (لا undici ولا socks) — امتداد للنقل القائم.
- **د (الإعدادات):** أحداث سلسلة تدقيق القضية + اعتمادات الوكيل في الخزنة — لا ملف إعدادات.
- **هـ (الفشل والحيوية والتأخير):** فشل-مغلق + حيوية عند البدء/التدوير + jitter اختياري.

## التنفيذ (P2-028 — أحمر-أولاً)

1. **أحمر-أولاً:** اختبارات تفشل قبل التنفيذ — حقل `route` في أحداث الشبكة والإسقاطات، رفض الوكيل غير المصرح به، فشل-مغلق عند فشل الوكيل (لا سقوط إلى direct)، رفض Tor غير المفعّل صراحة، قائمة حجب الدومينات الحساسة عبر Tor، حد المعدل المنفصل، سجل طلبات Tor.
2. حقل `route` في أحداث الشبكة (`EgressAuditEvent`) والإسقاطات.
3. إعدادات التوجيه في تخطيط الشبكة (`planNetworkRun`) + اعتمادات الوكيل من الخزنة.
4. الوضع المشدد (IP مثبت) في النقل، ثم وضع Tor (نطاق + الحجب + المعدل + السجل).
5. الحيوية عند البدء/التدوير + jitter الاختياري.
6. اختبار «لا سقوط صامت»: فشل الوكيل يظهر فشلاً صريحاً في التغطية والسجل.

## البدائل المرفوضة

- **حسب نوع الوكيل دون قيد الحاجة:** يفتح وضع نطاق لوكيل غير Tor بلا مبرر — مرفوض؛ النطاق فقط لـTor وبعلم صريح.
- **إرسال النطاق للوكيل الصريح (وضع تساهل عام):** يعطّل ضمانات SSRF — مرفوض.
- **سقوط إلى direct عند فشل الوكيل:** يكسر فشل-مغلق ويخفي المسار — مرفوض.
- **واجهة Tor منفصلة عن SOCKS5:** تعقيد بلا حاجة — مرفوض (البند ب).
- **حزم خارجية (undici/socks):** سطح هجوم واعتمادية خارجية — مرفوض (البند ج).
