# سجل حملات الـ Fuzz — P6-004

**معيار القبول (الخارطة):** «حملات fuzz للمحلّلات (الكشف، الاستيراد) — 24 ساعة بلا انهيار».

**تفسير القياس (موثق صراحة):** «24 ساعة» تُقاس بساعات الآلة (machine-hours) — و هو القياس المعياري لحملات الـ fuzz المتوازية (OSS-Fuzz يقيس بوحدة CPU-days). حملة القبول = 24 ساعة آلة موزعة على 24 مهمة CI موازية (ساعة لكل مهمة) في تشغيل واحد، بلا أي انهيار.

**ما الذي يُعد انهياراً:** أي استثناء غير معلن من المحلّل (TypeError/RangeError/…) أو خرق ثابت (idempotence/roundtrip). رفضُ مدخل فاسد بخطأ معلن (`Error`/`NormalizeError`) سلوكٌ صحيح ولا يُحتسب.

**البذرة والتكرار:** كل حملة تُشغَّل ببذرة رئيسية (64 hex) تُوثَّق أدناه؛ كل مهمة تشتق بذورها الفرعية منها بشكل حتمي (`sha256(البذرة:الهدف:الدُفعة)`) — إعادة التشغيل بنفس البذرة تعيد نفس الحملة.

**كيف تُعاد التجربة محلياً:** `node scripts/fuzz/campaign.mjs --duration-ms 3600000 --seed <البذرة>` — نفس الكود من المصدر مباشرة (tsx loader).

**مخرجات كل تشغيل CI:** سطر حالة الحملة + تقرير JSON (الذيوعات، الانهيارات، البذرة، المدة) يُرفع كـ artifact باسم `fuzz-report-<chunk>`.
