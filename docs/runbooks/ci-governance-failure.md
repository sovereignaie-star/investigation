# كتيب: فشل CI أو حوكمته (P7-006)

> حوارس الحوكمة (governance) إلزامية في CI ولا يجوز تعطيلها أبداً — هذا الحارس يحرس الحراس.

## متى يُستخدم

- فشل أي فحص على PR أو main (governance/ci/e2e/codeql/secrets/gitleaks).
- تعارضات دمج متتالية على ملفات الحوكمة (WORKLOG/STATUS/ROADMAP/package.json).

## الخطوات

1. ميّز الفشل الحقيقي من الفلكة: فحص docs-only فشل في e2e؟ أعد تشغيل المهمة الفاشلة (`gh run rerun <id> --failed`) قبل أي تغيير — فلكة السحب/الإفلات شائعة.
2. للفشل الحقيقي: استخرج السجل `gh run view <id> --log-failed` وأصلح السبب في كود/إعداد الفحص نفسه (لا تضع `continue-on-error`).
3. لتعارضات ملفات الحوكمة عبر PRs متوازية: أعد الأساس (rebase) على main وحل بالدامج: WORKLOG/DECLARED_LIMITS بدمج ours+suffix، STATUS/ROADMAP بدمج صفوف مفاتيحية، package.json باتحاد رموز السكربتات — ثم تحقق `node scripts/governance/check.mjs --consistency`.
4. تشبع المشغلات (حملات fuzz/Stryker تستهلك الفتحات): لا تطلق حملتين ثقيلتين متزامنتين؛ ألغي وأعد الجدولة بعد الاستقرار.

## التحقق

- `gh pr checks <N>` كله pass قبل الدمج — الدمج الآلي مشروط بالفحوص الخضراء كلها.
- بعد الدمج: `node scripts/governance/check.mjs --consistency` على main المحلي بعد reset.

## التصعيد

- فشل حارس حوكمة بعد 3 محاولات إصلاح جدية => شرط التوقف رقم 3 عند المالك مع تقرير الفشل كاملاً.
- فشل بنية تحتية GitHub (لا كودنا) => وثّق وأعد الجدولة؛ لا تحوّر الحارس لتجاوز الفشل.
