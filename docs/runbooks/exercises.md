## التمرين 1 — حادثة إصدار v0.1.0 (2026-10-24) — تمرين حقيقي لا محاكاة

- **متى:** 2026-10-24، بين 15:11Z و15:46Z.
- **ماذا:** أول تشغيل لحارس الإصدار على وسم `v0.1.0` فشل، مرتين، بأسباب مختلفة — ثم نجح.
- **الخطوات المتبعة (كتيب release.md قبل صياغته — هذه الحادثة هي مصدره):**
  1. فشل أول (تشغيل `40105870423`): سجل `gh run view --log-failed` أظهر `Unable to locate executable file: pnpm` — workflow الإصدار لم يثبت pnpm. الإصلاح: PR #416 أضاف `pnpm/action-setup@v6`.
  2. فشل ثانٍ (تشغيل `40107600441`): `Multiple versions of pnpm specified` — الإدخال الصريح `version: 10` عارض حقل `packageManager` في package.json. الإصلاح: PR #417 حذف الإدخال الصريح.
  3. حذف الوسم وإعادة إنشائه على الرأس المصحح: `git push origin :refs/tags/v0.1.0` ثم `node scripts/release/tag.mjs --create` و`git push origin v0.1.0`.
- **النتيجة:** التشغيل `40108453156` نجح (25 ثانية) وأنشأ https://github.com/sovereignaie-star/investigation/releases/tag/v0.1.0 — قبول P7-001 مُحقق ومقيس.
- **الدرس:** فشلان متتاليان بنفس الأصل (تهيئة بيئة الworkflow) — الحارس أخضر الآن لكن الدرس ينسخ: أي workflow جديد يختبر أول تشغيل حقيقي قبل اعتباره منجزاً. (وثّق أيضاً كإدخال WORKLOG في 2026-10-24.)
