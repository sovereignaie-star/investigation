# 2. سياسة اتخاذ قرار لكل أداة (DECISION_POLICY)


قبل البناء، يسجّل الوكيل بطاقة قرار لكل اسم أو قدرة:

| القرار | متى يستخدم؟ |
|---|---|
| `USE` | الأداة القائمة تؤدي المهمة بجودة مناسبة ويمكن استخدامها ضمن رخصتها وشروطها. |
| `WRAP` | الأداة جيدة، لكن تحتاج موصلاً موحداً إلى عقد Investigation Room. |
| `EXTEND` | توجد أداة صالحة لكن ينقصها محول أو اختبار أو إخراج معياري أو دعم لغة/صيغة. |
| `BUILD` | لا يوجد حل ملائم، أو يلزم منطق خاص لا تقدمه الأدوات الحالية. |
| `REJECT` | غير آمنة، مهجورة، غير قانونية في السياق، مرخصة على نحو غير ملائم، غير موثوقة، أو ذات تكلفة/مخاطر لا تبررها. |
| `RESEARCH` | لم تتوفر أدلة كافية على حالة الأداة أو ترخيصها أو واجهتها أو موثوقيتها. لا تُعرض في الإنتاج قبل حسمها. |

لا تُقيّم الأداة بالشهرة وحدها. يجب تقييم: الوظيفة، دقة النتائج، حداثة الصيانة، الرخصة، التبعيات، مخاطر سلسلة الإمداد، التكلفة، قيود الاستدعاء، جودة الوثائق، قابلية الاختبار، حماية البيانات، التغطية الجغرافية/اللغوية، ودعم API/CLI/SDK.
