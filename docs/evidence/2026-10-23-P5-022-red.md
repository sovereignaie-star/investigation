# P5-022 — الأحمر أولاً (RED): تصدير Markdown وصورة الرسم وهوية التقرير

التاريخ: 2026-10-23 — الترتيب: اختبارات T-EXP-001..008 كُتبت قبل وجود الميزة، وشُغّلت ففشلت (renderReportMarkdown is not a function — 7 فشلاً)، ثم نُفّذت.

## الأحمر الموثق (قبل التنفيذ)

```
$ pnpm vitest run packages/reports/src/export.test.ts

TypeError: renderReportMarkdown is not a function — 7 فشلاً (وT-EXP-008 فشل بالاستيراد)
```

## التنفيذ

- **Markdown:** `renderReportMarkdown(doc, identity?)` — حتمي، اتجاه عربي بالمحتوى، إحالات [n]، ملحق أدلة بالبصمات، وتصنيف السرية معلن عند تخصيص الهوية.
- **صورة الرسم SVG:** `renderGraphSvg(graph, identity?)` — تخطيط شبكي حتمي (أعمدة = جذر عدد العقد، بترتيب العقد كما وردت)، اتجاه rtl، تسميات عربية، وتصنيف الهوية بشريط علوي وعلامة مائية مائلة.
- **صورة الرسم PNG:** `renderGraphPng` — تنقيط بـresvg مع الخط العربي المضمّن في الحزمة (Noto Naskh Arabic — رخصة OFL موثقة في `packages/reports/fonts/`) وبلا خطوط النظام — الناتج حتمي عبر البيئات (مُثبت: نفس الرسم نفس البايتات).
- **هوية التقرير في HTML:** طبقة علامة مائية ثابتة (position: fixed + @media print) تظهر في كل صفحة عند الطباعة، وشريط تصنيف، وشعار ولون هوية — وبلا هوية يبقى القالب كما كان (توافق خلفي).
- **هوية التقرير في DOCX:** العلامة المائية في رأس كل صفحة (header1.xml)، والتصنيف في مقدمة الجسم.

## عيوب مكتشفة أثناء الدورة (موثقة بصدق)

1. كيانات HTML في دالة تهريب SVG انمحلت عند الكتابة (عيب معروف للكتابة النصية) — اكتُشف بفشل تحويل الملف وأُصلح ببناء الكيانات ببرمج حرفي (chr).
2. فحص رأس DOCX أمسك ملف العلاقات (header1.xml.rels) بدل الرأس نفسه — عيب إعداد اختبار؛ صُحح بنمط `/header\d+\.xml$/`.
3. إدراج التصنيف قبل تعريف مصفوفة الفقرات (منطقة ميتة) — اكتُشف بالتشغيل وأُعيد الترتيب.
