# P6-007 — سجل الحالة الحمراء (Red Evidence)

**التاريخ**: 2026-10-24
**الفرع**: `feat/P6-007-backup-restore`
**المهمة**: النسخ الاحتياطي والاستعادة — أمر `ir backup` لملف القضية + blobs، مشفر، مع اختبار استعادة آلي (القسم 10.4، بوابة G-40)

## الاختبارات الحارسة المكتوبة أولاً (قبل أي كود ميزة)

1. **`scripts/governance/backup.test.mjs`** — بوابة الحوكمة T-BK-001..003:
   - T-BK-001: أوامر `ir backup` / `ir restore` موثقة ومُوزَّعة في CLI مع `--backup-passphrase-file`
   - T-BK-002: مغلف النسخة الاحتياطية `packages/store/src/backup.ts` بتشفير حقيقي (Argon2id + AES-256-GCM) وأخطاء fail-closed
   - T-BK-003: تشغيل `scripts/backup/roundtrip.mjs` (الاستعادة الآلية الفعلية) ويجب أن ينجح
2. **`packages/cli/src/backup.test.ts`** — اختبارات Vitest: دورة CLI كاملة (backup → استعادة → verifyCase → قراءة الـblob ومطابقتها)، عبارة مرور خاطئة لا تستعيد شيئاً، واختبارات وحدة للمغلف (تلاعب/عبارة خاطئة)
3. **`scripts/backup/roundtrip.mjs`** — اختبار الاستعادة الآلي المستقل: قضية حقيقية + blob → حزمة موقعة → ملف مشفر → حذف الدليل → فك وت unpack → تحقق كامل وقراءة الـblob

## خطة الأخضر

- `packages/store/src/backup.ts`: `backupFile(pack, passphrase)` — اشتقاق مفتاح Argon2id (RFC 9106، نفس ثوابت الحالات) وختم الحزمة بـ AES-256-GCM؛ ملف JSON بصيغة `irbackup/1` (kdf/salt/iv/ct/tag) — لا نص صريح إطلاقاً؛ `openBackupFile` تفشل مغلقاً عند عبارة خاطئة أو تلف
- `ir backup <case-dir> <out.irbak> --key <private.pem> --backup-passphrase-file <f>`: packCase ثم backupFile
- `ir restore <backup.irbak> <case-dir> --backup-passphrase-file <f>`: openBackupFile ثم unpackCase (تحقق+بناء+إعادة تحقق) ثم تقرير verifyCase
