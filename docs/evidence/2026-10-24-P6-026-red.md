# P6-026 — دليل الفشل الأحمر (الاكتشاف الخامس للحملة)

- **التاريخ:** 2026-10-24
- **الهدف:** إغلاق الاكتشاف الخامس لحملة القبول (run 40085338964): مفاتيح أعضاء النموذج الأولي كمعرفات أنواع.

## الاكتشاف

4 مقاطع من تشغيل القبول (المقاطع 21/4/14/7) فشلت بنفس المثال المضاد (مطابقة لقلبها):

```
target: core.normalize
error: Error: invariant violation
counterexample: [{"type":"constructor","raw":"!"}]
{"totalIterations":145815416,"crashes":1,"seed":"d06be00c…","durationMs":2065269,"failedTarget":"core.normalize"}
```

## التشخيص

`normalizerFor` يبحث بخريطة كائن عادي: `const direct = EXACT[type]` — بمفتاح `constructor` يعيد `Object.prototype.constructor` (قيمة حقيقية!) فيُستخدم كدالة تطبيع: `Object("!", "constructor")` يعيد **String مُغلَّفاً (كائن)** بدل سلسلة بدائية. سلسلتان مغلفتان لا تتساويان أبداً بـ `===` فانكسر ثابت الإدقة؛ وخروج String مغلف إلى `canonicalKey` والمستهلكين خطر خلط أنواع. مفاتيح أخرى من أعضاء النموذج الأولي (`toString`، `valueOf`، `__proto__`…) بنفس الصنف.

## الحارس الأحمر

اختباران جديدان في `packages/core/src/normalize.test.ts` (قسم P6-026) فشلا بالسبب الصحيح قبل الإصلاح:
1. أنواع أعضاء النموذج الأولي = أنواع غير معروفة: بدائل نصية، سلسلة بدائية، إدقة.
2. `constructor` يسلك سلوك نوع غير معروف تماماً (حارس بنيوي).

## الإصلاح المخطط

بنيتي لا ترقيعي: خريطة الأنواع بنموذج أولي معدوم (`Object.assign(Object.create(null), {...})`) — كل مفاتيح أعضاء النموذج الأولي تصبح إخفاءً، فتسقط إلى بدائل النص كما هو مصمم.
