# P6-008 — سجل الحالة الحمراء (Red Evidence)

**التاريخ**: 2026-10-24
**الفرع**: `feat/P6-008-secure-delete`
**المهمة**: الحذف الآمن والاحتفاظ — UC-24: حذف قضية حذفاً آمناً وفق الاحتفاظ + شهادة حذف، لا بقايا في التخزين أو الكاش

## الاختبارات الحارسة المكتوبة أولاً (قبل أي كود ميزة)

1. **`scripts/governance/delete.test.mjs`** — بوابة الحوكمة T-DEL-001..003:
   - T-DEL-001: أمر `ir delete` موثق وموزع مع `--reason` إلزامي
   - T-DEL-002: `packages/store/src/delete.ts` بحذف آمن حقيقي (كتابة عشوائية قبل الحذف) وشهادة موقعة `irdeletion/1` ورفض الحالات غير القابلة للتحقق
   - T-DEL-003: تشغيل `scripts/delete/roundtrip.mjs` (الحذف الآلي الفعلي) ويجب أن ينجح
2. **`packages/store/src/delete.test.ts`** — اختبارات Vitest: حذف كامل + شهادة قابلة للتحقق خارج الشجرة المحذوفة، تمييز الحذف المبكر (early) عن الحذف بعد انتهاء الاحتفاظ (expired)، رفض حذف قضية فاسدة (fail-closed)، إلزام السبب
3. **`packages/cli/src/delete-cli.test.ts`** — دورة CLI: `ir delete` يحذف ويكتب الشهادة، ويرفض بلا سبب أو بلا مفتاح تثبيت
4. **`scripts/delete/roundtrip.mjs`** — الحذف الآلي المستقل: قضية+blob → تحقق → حذف آمن → الشجرة اختفت → الشهادة تتحقق

## خطة الأخضر

- `packages/store/src/delete.ts`: `deleteCase(dir, { actor, reason, key, clock })`:
  1. `verifyCase` أولاً — قضية لا تتحقق لا تُحذف (fail-closed)
  2. كتابة بايتات عشوائية فوق كل ملف (sqlite/wal/shm، blobs، المفتاح المغلف) ثم الحذف وإزالة الشجرة كاملة
  3. شهادة `irdeletion/1` موقعة Ed25519 (بنية JCS نفس بنية نقاط التفتيش): معرف القضية، طول السجل ورأسه وجذر Merkle، عدد الـblobs، سياسة الاحتفاظ وحالتها (early/expired)، السبب، الفاعل، الوقت
- `verifyDeletionCertificate(crt, publicKeyPem)` في `@ir/ledger` (نفس نمط verifyCheckpoint)
- `ir delete <case-dir> --reason <text> --key <private.pem>`: يكتب `<case-dir>.deleted.crt.json`
- قرار تصميمي موثق: الاحتفاظ حد أقصى وليس أجلاً أدنى — الحذف المبكر مسموح ويوسم `early` في الشهادة (الحد الأدنى من البيانات مبدأ مشروع)، وليس هناك أي `--force`
