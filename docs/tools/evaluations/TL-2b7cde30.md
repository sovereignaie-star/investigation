# تقييم TL-2b7cde30 — OpenSky Network (TR-040)

- **الرابط:** https://opensky-network.org/ (REST API: https://openskynetwork.github.io/opensky-api/rest.html)
- **المصدر في الكتالوج:** مصادر الطيران (رمز ICAO24/نداء ← رحلات)
- **تاريخ التقييم:** 2026-10-15
- **المقيِّم:** الوكيل الهندسي (المراجعة الأمنية: مراجعة D-8 على PR)

## القيمة للمستخدمين (PR-1..PR-6)
- يجيب عن: «ما الرحلات المرتبطة بهذا الطائرة (ICAO24) أو هذا النداء؟» — تحقق حركي لطائرة مشتبهة.

## الشروط والترخيص
- **الترخيص:** LC-C — **حساب مجاني بالتسجيل**؛ المصادقة حصراً OAuth2 client-credentials (منذ 2026-03-18 لم تعد كلمة المرور مقبولة): إنشاء API client من صفحة الحساب ثم `client_id` + `client_secret` (توكن Bearer صلاحيته 30 دقيقة).
- **الحدود:** نظام أرصدة: مستخدم مسجَّل 4,000 رصيد/يوم (مجهول: 400/يوم، وبيانات حالية فقط بلا تاريخ)؛ التكلفة حسب المساحة/الأيام المطلوبة.
- **المطلوب من المالك:** تسجيل حساب (مجاني) وإنشاء API client — **إجراء متاح للمالك فوراً**.

## الحساسية (E-02)
- عادي: طائرات ورحلات ليست أشخاصاً طبيعيين.

## الاستقرار
- خدمة بحثية عامة مستقرة منذ سنوات؛ المصادقة انتقلت إلى OAuth2 (2026) — مخطط موثق.

## القرار
- **فئة الترخيص:** LC-C.
- **القرار:** معلق حتى تسجيل المالك (مجاني) وإنشاء بيانات الاعتماد — البند **blocked على إجراء المالك** لا على قدرة فنية. عند توفر `client_id/client_secret`: التنفيذ مباشر (نمط TR-001 مع إدارة توكن OAuth2 في المشغّل).

## سجل التنفيذ (2026-10-16، فرع `feat/P2-012-tr-040-opensky`)

- **الحالة:** منفذ كاملاً بعد قرار المالك ADR-27 (استثناء OAuth2 للتوكن) — انظر أدناه.
- **القرار المعماري المطلوب أولاً:** مواصفة المصدر (OAuth2 client-credentials حصراً: POST إلى نقطة التوكن) تعارضت مع ADR-08 («لا جسم طلب — GET وHEAD فقط»)، فتوقف التنفيذ عند الفجوة وفق توجيه المالك (البند 5)، وقرر المالك الاستثناء بصياغة حاكمة → **ADR-27** (`docs/adr/ADR-27-oauth2-token-post.md`) والحد المعلن **L-19**.
- **التنفيذ (سلسلة POST كاملة):** `TransformHttp.post` (العلامة oauth2Token دوماً — لا مسار POST آخر) → `HttpTransport`/IPC المعزول (الجسم نص يمر للأب الموثوق) → محوّل التسجيل (لا يسجل جسم استجابة التوكن قطعاً) → محول بوابة الخروج → **بوابة الخروج**: ترفض أي POST بلا علامة أو لغير مضيف التوكن المثبت (`oauth2AuthHosts` — حالياً `auth.opensky-network.org` وحده؛ الإعداد من كود الأب الموثوق؛ تغييره = ADR جديد)، وتفك الجسم وتشترط بالضبط `grant_type=client_credentials` + `client_id` + `client_secret`، وتجرد محتواه **كأزواج مفكوكة ك سطح الاستعلام** (فحص الأشخاص الطبيعيين مفعّل عليه — مقيس: معرف شخصي في client_id يُرفض natural_person قبل DNS؛ وبقية قراءاته ليست بيانات قضية فلا يطلب sends لها)، والنقل الإنتاجي (node-transport) يكتب الجسم للـPOST فقط.
- **TR-040 نفسه:** المفتاحان من `IR_OPENSKY_CLIENT_ID`/`IR_OPENSKY_CLIENT_SECRET` (بيان يعلن env للمشغّل المعزول)؛ بلا أي منهما فشل-مغلق قبل أي نقل [مقيس: صفر طلبات]؛ POST التوكن (جسم ثابت من أسرار المشروع فقط) ثم Bearer على نداءات API؛ **التجديد**: 401 من API ← إعادة اكتساب التوكن مرة واحدة وإعادة المحاولة [مقيس: 4 طلبات]؛ التوكن في ذاكرة المشغّل فقط (لا يظهر في الأدلة ولا في أي مخرجات — مقيس). عمليتان: icao24 ← `/api/flights/aircraft` (نافذة 24 ساعة تنتهي بالأمس — المصدر لا يخدم إلا الرحلات المنتهية)؛ نداء ← `/api/states/all` مرشّح محلياً (المصدر لا يدعم فلترة النداء) يعيد عناوين icao24 تتغذى التوسعة على مسار الرحلات.
- **نوعا كتالوج جديدان:** `icao24` (`^[0-9a-f]{6}$`) و`flight_callsign` (`^[A-Z0-9]{2,8}$`) في Device — الكتالوج 385 نوعاً (مقيس، بلا ازدواج).
- **الأدلة [مُقيس]:** 9 اختبارات عقد (7 داخل العملية + 2 معزولتان على مسار الإنتاج) في `packages/transforms/src/tr-040.test.ts`؛ 7 اختبارات سياسة ADR-27 في `packages/egress/src/oauth2-post.test.ts` (تثبت أيضاً أن الجسم لا يدخل أي حدث تدقيق)؛ حُدّث اختبار مصفوفة SSRF T-SEC-SSRF-043 من «لا قناة جسم» إلى قاعدة ADR-27 الجديدة مع وثيقة التغطية. السلسلة الكاملة: 116 ملفاً / 1618 ناجحاً / 6 متخطاة؛ lint/typecheck/build exit 0.
- **ما لم يُقس:** تشغيل حي بمفاتيح فعلية (التسليم `IR_OPENSKY_CLIENT_ID/SECRET` عند المالك؛ الفشل-المغلق بدونهما مقيس). طلبات states/all الحية كبيرة (سقف 20MB في البيان).
